Push a Branch. It runs on your Mac.

  • mainyour Production Branch app.example.comthe Stable Target
  • feature-xany other Branch feature-x.app.example.coma Preview, with its own data and logs
  • files on diskno push needed 127.0.0.1:3000the Working copy

Rig deploys your Projects to the Mac on your desk. Each Branch gets a hostname, health checks, logs, and a record of every deploy. There is no cloud account and there are no containers.

Set up a Project

  1. Install the daemon

    rigd starts at login and runs everything: deploys, ports, health checks, and logs. 

    rigd install

  2. Describe the Project

    This writes a rig.yaml with your Services and domain, and adds a rig git remote. You can edit it later from the dashboard; comments are kept. 

    rig init --service web --run "bun run start" --domain app.example.com

  3. Push

    Rig builds the commit, starts it, waits for it to be healthy, and points Caddy at it. 

    git push rig main
git push rig feature-x

The words Rig uses

Project
One repository with a rig.yaml: its Services, Tools, domain, and proxy map. Every address is checked to be localhost-only.
Target
One running copy of a Project. The Working copy runs the files on disk, the Stable Target follows your Production Branch, and every other Branch becomes a Preview on its own subdomain.
rigd
The daemon that does the work. The rig command, git push rig, and the dashboard all ask it, so they always agree.
Route
Rig writes the Caddy site for each Target that has a hostname and reloads Caddy. This page reaches you that way.
Activity
Every deploy, start, and stop is kept with its outcome. Status shows what Rig observed, not what it expects.
Doctor
Checks the Mac and each Project, and says how to fix what it finds.
Recipe
A ready-made Service block for Postgres or Convex. Rig can compare yours with newer versions.

The dashboard controls rigd on the Mac that serves this page. It opens only from that Mac or from addresses that Mac trusts.
